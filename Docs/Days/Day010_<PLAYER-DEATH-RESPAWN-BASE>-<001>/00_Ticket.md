[Task ID]

PLAYER-DEATH-RESPAWN-BASE-001

[Title]

사망 → 리스폰 흐름을 서버 권한 기준으로 일관되게 처리한다

[Background]

지금까지의 티켓들은
- 입력 → 의도(Intent)
- 서버 검증 → 적용
- UI / 피드백

까지는 잘 다뤘는데,
플레이어 생명 주기(Life Cycle) 는 아직 정리되지 않았어.

실무에서는

“죽었을 때 누가, 언제, 무엇을 리셋하는가?”
이게 안 정리돼 있으면

- UI 꼬임
- 입력 먹통
- 클라/서버 상태 불일치
가 바로 터진다.

이번 티켓은 전투 결과의 종착점을 다루는 기본기 티켓이야.

[Requirements]
- 플레이어 체력이 0 이하가 되면
    - 서버에서 사망 판정
    - 입력 불가 상태로 전환
    - 사망 상태가 클라이언트에 동기화됨
- 일정 시간 후 서버 주도로 리스폰 수행
    - 위치 초기화
    - 체력/상태 초기화
    - 입력 다시 가능
- 리슨 서버 + 클라이언트 1명 환경에서
    - 두 플레이어 모두 동일한 흐름을 거칠 것

실패/예외 케이스
- 클라이언트에서 임의로 체력을 0으로 만들어도
서버 판정 없이는 사망 처리되지 않아야 함

[Constraints]
- UE 5.4 기준
- Tick 사용 금지 (Timer 사용)
- 사망/리스폰 로직은 Character가 독점하지 말 것
- 네트워크 권한 흐름 명확히 구분
    - 판정: Server
    - 연출/UI: Client
- 이후 Spectator / Team Respawn 으로 확장 가능해야 함

[Definition of Done]
- 로그로 아래 흐름이 명확히 확인됨
```
[Client] HP <= 0 요청
→ [Server] Death 승인
→ [Multicast] Death 상태 전파
→ [Server] Respawn 타이머 만료
→ [Multicast] Respawn 처리
```
- "입력 불가 / 가능 전환이 명확히 동작
- "UI 상태와 실제 입력 상태가 어긋나지 않음
- "죽었다가 살아난다”는 개념이 구조적으로 설명 가능
